TLX on gfx1250 (RDNA4)

TDM descriptors and expected support on next-gen AMD.

The distinguishing TLX feature on this target is TDM (Tensor Descriptor Machine): hardware descriptors with fused multi-member loads, multicast, and prefetch. Hardware tags follow TLX.

MXFP GEMM kernels

mm_mxfp/gfx1250.py holds two MXFP GEMM kernels for C = (A * a_scale) @ (B * b_scale)^T with E8M0 block scales (one per 32 K elements), FP32 accumulation, and FP32 or FP16 output. mxgemm_tdm_pipelined launches either one with every schedule option, and matmul is its config-dictionary form.

•
mxgemm_tdm_pipelined_kernel follows the Gluon MXFP GEMM example: one

output tile per program, FP8 or FP4 A and B, optional A scales, baseline or sliced K/N/MNK schedules, and none/2way/4way/partial TDM fusion. Its grouped modes back grouped_gemm_mxfp/gfx1250.py.

•
mxgemm_tdm_persistent_kernel is a persistent kernel for 256x256 output

tiles with FP8 E4M3 A and FP8 E4M3 (A8W8) or FP4 E2M1 (A8W4) B. It backs mm_mxfp and is described below.

TILES_PER_WARP=(M, N) (--tiles_per_warp M N on the command line) selects the WMMA tiles per warp, 2 2 by default.

Persistent kernel design

Work split. Each program walks a sequence of output tiles in group-M order. Four waves, one per SIMD, split a 256x256 tile 2x2, so each wave keeps a 128x128 FP32 accumulator in registers and issues v_wmma_scale_f32_16x16x128_f8f6f4 for its four 64x64 quadrants. A8W8 uses K blocks of 128 (BK128); A8W4 uses BK256.

Input ring. A, B, and both scale tensors stream into LDS through a ring of NUM_BUFFERS TDM stages. Loads use partial fusion: A data and its scales are issued by waves 0 and 2, B data and its scales by waves 1 and 3, so each wave issues two TDM instructions per stage. Each K step

1. waits at a workgroup barrier until all waves have read the slot to refill, 2. refills that slot with a stage NUM_BUFFERS steps ahead, 3. waits for the next stage's TDM transfers (s_wait_tensorcnt), 4. waits at a workgroup barrier until the stage is visible to all waves.

Matrix instructions of the current step are scheduled across this sequence, and operand reads for the next step start as soon as its stage is visible. Scales are read with the payloads into the WMMA scale operands.

Tile transition. With cross-tile prefetch (A8W8), the last NUM_BUFFERS K steps of a tile refill each freed slot with the next tile's inputs, so the next tile's data is in flight while the current tile finishes. The C epilogue converts the accumulators to the output type, writes them to LDS in 64-row chunks, and stores each chunk with a TDM store:

•
A8W8 stages C through dedicated LDS slots (OUTPUT_C_SLOTS). A chunk

waits only when its slot's previous TDM store is still pending.

•
A8W4 stages C in A input stages it no longer reads, keeping the A slot

pitch so retiring a C slot frees exactly one input stage. Without cross-tile prefetch, each tile is primed after its C stores.

Clusters. CLUSTER_SIZE workgroups form a cluster whose matching TDM loads are multicast. A grid layout RxC maps a cluster onto R M tiles by C N tiles, so each A tile is loaded once for C workgroups and each B tile once for R. A cluster barrier every CLUSTER_BARRIER_INTERVAL K blocks keeps the members' requests close enough to merge; each workgroup's own waits protect its LDS, so the barrier is not needed for correctness. XCD_REMAP permutes whole clusters across XCDs so that clusters on one XCD share inputs.

A8W8 options.

•
STATIC_SLOT_UNROLL unrolls the three- or four-stage steady loop by the

ring depth, so every step reads a loop-invariant LDS slot and operand addresses leave the loop. Each tile's first step is peeled so its WMMAs read zero accumulators as an inline constant. The A and B slots are then split into 64-row pieces that alternate between two LDS partitions, reducing contention among the waves that read one operand subtile.

•
OVERLAP_PEEL runs each next tile's first K step inside the current

tile's C epilogue: after a C quadrant is staged, its registers take that quadrant's next-tile WMMAs, which execute while later C chunks wait for slots. The next tile's first refill is issued before the last C chunks, because TDM operations complete in order.

•
Without the static unroll, the three-stage loop reads each operand's

scale before its payload, so each quadrant waits only for its own LDS reads.

•
A four-stage ring uses two smaller C slots (64x64 for FP32, 64x128 for

FP16) and a grouped operand prefetch.

•
MERGED_HANDOFF_BARRIER (four-stage static loop) replaces the K step's

two workgroup barriers with one, split around register-only work. Each step reads both second halves of its slot during the C00 WMMAs, waits for its share of the next stage, signals (tlx.named_barrier_arrive, which lowers to s_barrier_signal), runs the C01 WMMAs, waits (tlx.named_barrier_wait, s_barrier_wait), then refills the slot and reads the next stage across the C10 and C11 WMMAs. The one rendezvous orders the slot's last reads before its refill and publishes the next stage to every wave, so the operand reads are relaxed and Membar adds no barriers of its own.

•
STATIC_CLUSTER_STEPS drops the run-time cluster-rendezvous test from the

unrolled steps that can never refill a rendezvous stage.

•
SCALE_LAYOUT="wave256" uses a second preshuffled scale format

(pack_scale(x, layout="wave256")): one row per 256 M/N rows, ordered per K128 step as [row bit 5][row % 32][row bit 7][row bit 6][4 K], so each lane's 16 bytes are the four scale dwords its wave needs for both 128-row quadrants. The merged step reads each operand's scales with one ds_load_b128 and splits the quadrants in registers; the other schedules read one quadrant per ds_load_b64. The default block128 format stores one row per 128 rows.

A8W4 options. SPLIT_CLUSTER_BARRIER signals the periodic cluster rendezvous before independent matrix work and waits just before the refill. EARLY_C_STORES interleaves the final quadrant dots with C stores.

FP16 output rounds the FP32 accumulators once in registers before staging, halving C's LDS, TDM, and memory traffic. C buffers that alias input slots hold twice the rows at the same pitch.

Requirements

The persistent kernel requires FP8 E4M3 A with A scales, transposed B ([N, K]), scales preshuffled with pack_scale (wave256 only for A8W8 BK128), partial TDM fusion, and full 256x256 output tiles with at least NUM_BUFFERS K blocks. A8W8 uses two to four BK128 stages; A8W4 uses three BK256 stages (FP8 B with BK256 uses two). Clustering requires GROUP_SIZE_M 4 or 8, full M groups, and a program count divisible by 16 that divides the output tile count. mxgemm_tdm_pipelined validates these constraints before launching.

Benchmark

Run from the repository root in an environment configured for gfx1250:

python third_party/tlx/ops/kernels/mm_mxfp/bench_gfx1250.py --csv mxfp.csv
python third_party/tlx/ops/kernels/mm_mxfp/bench_gfx1250.py --variant mx8xmx4 -M 8192 -N 8192 -K 4096
python third_party/tlx/ops/kernels/mm_mxfp/bench_gfx1250.py --dry-run

Timing repeats eager batches of --benchmark-num-iters milliseconds: batches run for --warmup-seconds, then the median batch over --duration-seconds is reported. The device clock depends on load, so keep the timing settings fixed when comparing configurations. The summary prints the AMD code generator revision. The kernels are tuned with the AMDGPU code generator pinned in cmake/amd-llvm-info.json. Builds with cmake/meta-llvm-info.json compile the code generator against the core LLVM instead; set TRITON_AMD_CODEGEN_PATH to the pinned library to use it.

The standalone command line runs one shape, for example the A8W8 default at 8192 cubed:

  --cluster_size 16 --cluster_layout 4x4 --cluster_barrier_interval 8 --xcd_remap chunked \
  --static_slot_unroll --overlap_peel --output_c_slots 3 --num_programs 256

Portable values and types

The following helpers construct values, types, layouts, or metadata through portable TLX paths: assume_uniform, zeros, dtype_of, size_of, get_fp8_format_name, assert_same_layout, dump_layout, storage_alias_spec, allocate_tensor_descriptor, thread_id, num_warps, layout_encoding, shared_layout_encoding, swizzled_shared_layout_encoding, swizzled_layout, padded_shared_layout_encoding, shared_linear_layout_encoding, slice_layout, DummyRegisterLayoutEncoding, layout, storage_kind, reuse_group, reuse_group_type, reuse_group_ir_type, storage_alias_spec_type, storage_alias_spec_type_class, buffered_tensor, buffered_tensor_type, mbarrier, mbarrier_type, and async_token.

Constructing a type does not enable an unsupported storage kind or matrix instruction. In particular, storage_kind.tmem is not an AMD allocation mode. See memory and layout control.

Unsupported operations

•
buffer_load_to_local is restricted to CDNA3/CDNA4 by the target verifier. It is rejected on gfx1250; use TDM descriptor loads or the non-bulk pointer-based copy path.
•
amd_scheduled_mfma and amd_mfma_commit require gfx942/gfx950 MFMA versions. They are rejected on gfx1250, which uses WMMA-v3.
•
amd_mfma_layout can construct a CDNA layout object, but is not the gfx1250 matrix-compute layout. Use require_amd_wmma_layout instead.
•
clock64 currently emits llvm.amdgcn.s.memtime, which gfx1250 does not support. The frontend symbol exists, but LLVM cannot select that timer instruction for this target; see the timer lowering.
•
NVIDIA TMEM operations and async_load(bulk=True) are not gfx1250 copy/compute paths.

The CDNA-only restrictions are enforced by the AMD verifier and matrix-instruction selection.

Notes

•
WMMA queuing is a compiler launch option (enable_wmma_queuing), not a tlx.amd_set_wave_sched_mode builtin. The AMD backend sets the wave-scheduler-mode register; see the compiler options.
•
Fused TDM loads require disjoint warp masks and support at most 5 multicast recipients. async_amd_descriptor_wait takes pending counts or tokens, not both.
