TLX on gfx1250 (RDNA4)

TDM descriptors and expected support on next-gen AMD.

The distinguishing TLX feature on this target is TDM (Tensor Descriptor Machine): hardware descriptors with fused multi-member loads, multicast, and prefetch. Hardware tags follow TLX.

Supported extension builtins (tlx.*)

The entries below distinguish existing target-specific tests from source implementation. Implemented means the frontend and AMD lowering provide that operation; it does not claim that every dtype, layout, or scheduling mode has been executed on gfx1250. Runtime coverage remains limited to the cases exercised by the linked tests.

The code-generation tests include gfx1250 shared-memory gather/scatter, WMMA, TDM, multicast, and grouped-GEMM compilation. The TDM tests also exercise barrier arrival/wait and inter-wave token waits. Shared-memory gather/scatter use the portable lowering. Copy and wait handling are implemented in the AMD memory lowering.

Compile-only availability tests cover all six listed buffer-atomic dtypes on gfx1250. This group has source implementations, but existing gfx1250 runtime tests do not establish coverage of every direct API above. The relevant evidence is the buffer/atomic lowering, AMD memory lowering, warp-predicate lowering, and thread/timer lowering.

Portable values and types

The following helpers construct values, types, layouts, or metadata through portable TLX paths: assume_uniform, zeros, dtype_of, size_of, get_fp8_format_name, assert_same_layout, dump_layout, storage_alias_spec, allocate_tensor_descriptor, thread_id, num_warps, layout_encoding, shared_layout_encoding, swizzled_shared_layout_encoding, swizzled_layout, padded_shared_layout_encoding, shared_linear_layout_encoding, slice_layout, DummyRegisterLayoutEncoding, layout, storage_kind, reuse_group, reuse_group_type, reuse_group_ir_type, storage_alias_spec_type, storage_alias_spec_type_class, buffered_tensor, buffered_tensor_type, mbarrier, mbarrier_type, and async_token.

Constructing a type does not enable an unsupported storage kind or matrix instruction. In particular, storage_kind.tmem is not an AMD allocation mode. See memory and layout control.

Unsupported operations

•
buffer_load_to_local is restricted to CDNA3/CDNA4 by the target verifier. It is rejected on gfx1250; use TDM descriptor loads or the non-bulk pointer-based copy path.
•
amd_scheduled_mfma and amd_mfma_commit require gfx942/gfx950 MFMA versions. They are rejected on gfx1250, which uses WMMA-v3.
•
amd_mfma_layout can construct a CDNA layout object, but is not the gfx1250 matrix-compute layout. Use require_amd_wmma_layout instead.
•
clock64 currently emits llvm.amdgcn.s.memtime, which gfx1250 does not support. The frontend symbol exists, but LLVM cannot select that timer instruction for this target; see the timer lowering.
•
NVIDIA TMEM operations and async_load(bulk=True) are not gfx1250 copy/compute paths.

The CDNA-only restrictions are enforced by the AMD verifier and matrix-instruction selection.

Notes

•
WMMA queuing is a compiler launch option (enable_wmma_queuing), not a tlx.amd_set_wave_sched_mode builtin. The AMD backend sets the wave-scheduler-mode register; see the compiler options.
•
Fused TDM loads require disjoint warp masks and support at most 5 multicast recipients. async_amd_descriptor_wait takes pending counts or tokens, not both.
