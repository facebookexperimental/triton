Shared/unit controls are explicitly restricted. The independent project gate is unchanged; a reference failing it is diagnostically timed and marked ineligible. That does not assert an upstream bug under a different accuracy target.

The focused [framework report](FRAMEWORK_COMPARISON.md) includes the best passing measured configurations and three fresh repeat rounds. SGLang standard/Lean use the same split sweep; full-FP8 unit GQA now passes in the standard kernel with a common Q scale folded into softmax scale. No arbitrary per-query-head scale support is attributed to it.

Framework routing was checked against pinned production code, with snapshots and hashes in [framework_route_audit.json](results/2026-11-05_framework_decode/framework_route_audit.json):

- [vLLM Triton backend](https://github.com/vllm-project/vllm/blob/86fdabec0c82d0470c160aa4df7602ac22c207e6/vllm/v1/attention/backends/triton_attn.py) supplies16 split segments, FP32 scratch and threshold128/KV-heads. Tensor descriptors default off on ROCm. Supplying none of these scratch arguments in the earlier adapter forced2D; step09 corrects this.
- [vLLM ROCm AITER unified backend](https://github.com/vllm-project/vllm/blob/86fdabec0c82d0470c160aa4df7602ac22c207e6/vllm/v1/attention/backends/rocm_aiter_unified_attn.py) calls AITER for causal attention, optionally with shuffled gfx1250 KV. Step09 reports one deduplicated packed AITER operator control; it is not a separately measured framework server. Noncausal attention uses the vLLM fallback.
- [SGLang AITER backend](https://github.com/sgl-project/sglang/blob/9b6c796151f836907fbf93265984006ecfd6a790/python/sglang/srt/layers/attention/aiter_backend.py) can quantize BF16 Q when using FP8 KV through unified attention. Its vectorized5D route uses `pa_decode_gluon`, which is limited to [gfx942/gfx950 at this pin](https://github.com/ROCm/aiter/blob/796ff6a35588058516bcaf13129bd0f0b22fb9ae/aiter/ops/triton/gluon/pa_decode_gluon.py). Those paths cannot be automatically labeled equivalent BF16-Q gfx1250 measurements.
- [SGLang Triton backend](https://github.com/sgl-project/sglang/blob/9b6c796151f836907fbf93265984006ecfd6a790/python/sglang/srt/layers/attention/triton_backend.py) supplies the direct decode kernels tested here. Specialized MLA/CDNA paths have different head dimensions and architecture gates; they are outside these D64/D128 gfx1250 cases.

AITER/TokenSpeed contribute packed movement, WMMA/grouped-query and pipeline ideas; vLLM contributes scale interfaces/online-softmax comparisons; SGLang contributes split/merge, persistent scheduling and gfx1250 numerical precautions. The TLX implementation is independent.

## November9 routing correction

At the pinned AITER revision, Gluon2D eligibility requires equal Q/KV dtypes. The BF16-Q/FP8-KV SWA128 control therefore uses `kernel_unified_attention_2d` (Triton), even when the unified launcher requests Gluon. Nonwindowed mixed-dtype3D can use Gluon. Gluon imports were verified healthy. A diagnostic host eligibility override into unmodified Gluon2D fails this project's numerical gate (~99% elements, maxabs~0.282), so its timing is excluded. [Diagnostic data](results/2026-11-09_optimization/aiter_forced_swa.json). This correction changes attribution; stock AITER unified remains the default measured reference.
