Each reported value is the median of three fresh order-rotated round medians. Each round uses fifteen GPU graph-batch measurements of twenty invocations. All72 selected verification runs pass the unchanged FP32 oracle gate (`atol=5e-4,rtol=1e-2`). Packing, compilation, quantization and oracle setup are excluded. Repeated inputs follow the same warm-cache protocol; clocks are unlocked and no hardware utilization claim is made. The CSV and table below retain round ranges.

The first attempted shared run is excluded: its immediately preceding snapshot showed19% GPU activity and16046MiB already in use. It is preserved under `shared/`; the reported run is `shared_verified/`, with a fresh idle snapshot (0% activity,161MiB). The native companion also began idle. This prevents those first samples from entering the medians; shared host activity and unlocked clocks still limit comparisons across dates.

Runtime: same selected gfx1250,96-CU/144-GiB agent,CUDA_VISIBLE_DEVICES=0 in `adkankar-tlx-opt-20261105`; source-built TLX3.9.0+fb,Torch2.12/ROCm10.1. TLX and pinned GPU reference source hashes match the November5 manifest. [Pinned source paths and contract limits](REFERENCES.md). No GPU kernel changes.

`_kvtd3d` keeps the upstream GPU bodies but uses KV tensor descriptors without Q/output descriptors and tile64. `_3d_tuned` changes the Python decode tile helper. These are launch-tuned controls, not stock ROCm defaults. Stock3D supplies FP32 split scratch,16 segments,threshold128/KV-heads and descriptors disabled. The nominal split parameter in raw TLX call parameters does not select its actual launch: TLX uses automatic dispatch.

To repeat, use `compare_framework_decode.py --repeat-only --aiter-companion` with the three shared case names and `--extend-from results/2026-11-05_framework_decode/framework_routes` (full paths relative to the experiment directory). Use the three per-head case names with `--repeat-only --extend-from .../final` for the native companion. [Environment and timing reproduction](REPRODUCE.md).
